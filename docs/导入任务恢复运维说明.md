# 导入任务恢复运维说明

用于处理迁移前遗留、长时间停在 `structuring` 的导入任务。服务启动不会自动修改这些业务数据。

1. 先确认任务确实卡住，避免干预仍在运行的任务：

```sql
SELECT id, file_name, status, updated_at, stage_error
FROM import_jobs
WHERE status = 'structuring'
  AND updated_at < now() - interval '1 hour'
ORDER BY updated_at;
```

2. 备份数据库并人工核对任务 ID 后，只将指定任务标为失败。`job_id` 必须替换为核对过的 UUID：

```sql
UPDATE import_jobs
SET status = 'failed',
    stage_error = '运维确认旧任务卡在 structuring，可安全重试',
    updated_at = now()
WHERE id = 'job_id'
  AND status = 'structuring';
```

3. 使用管理员会话调用现有接口重试：

```bash
curl -X POST \
  -H 'Content-Type: application/json' \
  -H 'Origin: https://your-app.example' \
  -b admin-cookie.txt \
  https://your-app.example/api/v1/admin/import-jobs/job_id/retry
```

重复调用会被现有状态保护，不会重复创建导入项或已发布题目。执行后检查任务状态和 `import_items` 数量；不要批量更新全部 `structuring` 任务。
