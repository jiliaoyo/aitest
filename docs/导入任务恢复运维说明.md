# 旧版导入任务恢复运维说明

> 仅适用于迁移前遗留数据。当前版本只接收结构化 JSON，并同步进入 `review_ready`；
> 不会创建 `structuring` 任务，也没有 `/admin/import-jobs/{id}/retry` 接口。

用于识别迁移前遗留、长时间停在 `structuring` 的导入任务。服务启动不会自动修改这些业务数据。

1. 先确认任务确实卡住，避免干预仍在运行的任务：

```sql
SELECT id, file_name, status, updated_at, stage_error
FROM import_jobs
WHERE status = 'structuring'
  AND updated_at < now() - interval '1 hour'
ORDER BY updated_at;
```

2. 备份数据库并人工核对任务 ID 后，只将指定任务标为失败。`job_id` 必须替换为核对过的 UUID：

```sql
UPDATE import_jobs
SET status = 'failed',
    stage_error = '运维确认旧任务卡在 structuring，可安全重试',
    updated_at = now()
WHERE id = 'job_id'
  AND status = 'structuring';
```

3. 从原始 OCR 工程重新导出 `{"items":[...]}` 结构化 JSON，通过当前管理端新建导入任务。
   旧任务只保留追溯用途，不要复制其半成品 `import_items`，也不要批量更新全部
   `structuring` 任务。新任务发布前逐题核对，避免与旧任务已经发布的内容重复。
