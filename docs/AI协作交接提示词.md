# AI 协作交接提示词

本文件用于把产品需求交给其他 AI。使用前请同时提供同目录下的《AI刷题App-产品需求文档.md》，并要求对方不要自行扩大首版范围。

## 1. 前端产品设计与原型提示词

```text
你是一名资深教育产品设计师和 Vue 前端架构师。

请完整阅读随附的《AI刷题App-产品需求文档.md》，为该产品设计首版 Web 端信息架构和高保真原型方案。不要添加 PRD 未要求的社区、会员、排行榜、课程商城或聊天机器人。

技术与产品约束：
- 前端最终使用 Vue 3 + TypeScript。
- 首发为 JLPT 文字词汇、语法、阅读题，不做听力。
- 一批题默认 20 道，答题中不能显示答案、对错或解析。
- 官方/人工答案、AI 判定、AI 解析、待分析必须有明显且一致的状态标识。
- 同时设计学习端和管理端，优先保证答题、结果分析、非结构化导入审核三个流程。
- 桌面优先但必须响应式支持手机浏览器。
- 日文长文、假名、选项和材料题需要良好的阅读体验。

请按顺序输出：
1. 站点地图和导航结构。
2. 三条核心用户流程：创建并完成练习、查看结果并专项重练、管理员导入并审核题目。
3. P0 页面清单以及每页的目标、模块、主要操作、空状态、加载状态、错误状态和权限状态。
4. 答题页、结果页、学习仪表盘、导入审核页的详细布局说明。
5. 设计 token 建议：颜色、字号、间距、圆角和状态色；不要让答题页颜色提前暗示对错。
6. 可复用组件清单，但避免为单一页面创建过度抽象的组件体系。
7. 适合直接实现的 Vue 路由结构和页面级组件树。
8. 需要产品确认的问题，最多 5 个，并为每个问题给出推荐默认值。

验收重点：
- 提交前绝不泄露答案相关字段。
- 结果页不会把 AI 估算混成官方正确率。
- 材料题在桌面和手机上都能持续查看共享材料。
- AI 处理中、部分失败、内容被下架等边界状态有明确界面。
- 管理员可以原文对照审核 Agent 整理的结构化题目。
```

## 2. 后端架构与接口设计提示词

```text
你是一名资深 Go 后端架构师。

请完整阅读随附的《AI刷题App-产品需求文档.md》，为首版制定可直接开发的后端技术方案。保持单体优先，不要预设微服务、Kafka、向量数据库或独立搜索集群；只有在明确说明现有方案无法满足哪项需求时才能建议新增基础设施。

固定技术栈：
- Go 后端。
- PostgreSQL 数据库。
- Vue 3 + TypeScript 前端通过 HTTP API 调用。
- AI 解析、无答案题判定和题库整理需要异步执行。

必须满足：
- 官方/人工答案优先，AI 不能覆盖权威答案。
- 批次提交前 API 不返回答案、解析或可推断答案的字段。
- 作答自动保存，批次提交和判分幂等。
- 题目修改或下架后，历史练习仍可复现。
- 用户学习数据严格按账号隔离。
- AI 故障不影响有答案题判分。
- 非结构化导入只生成草稿，人工审核后发布。
- 学习统计以原始作答为事实来源，可以重算。

请按顺序输出：
1. 单体应用模块划分和请求/异步任务流程图。
2. PostgreSQL 表设计，包括主键、关键字段、枚举、外键、唯一约束和主要索引。
3. 题目、材料题、答案来源、题目版本、练习快照、知识点统计和导入任务的建模说明。
4. REST API 清单，按学习端、管理端分组；给出关键请求/响应示例。
5. 明确提交前与提交后两套题目响应 DTO，证明不会泄露答案。
6. 批次创建、自动保存、提交、确定性判分、AI 判分、统计更新的事务和幂等策略。
7. 基于 PostgreSQL 任务表的 worker 设计，包括抢占、租约、重试、失败和死信处理；不要先引入新消息队列。
8. AI 调用的版本化 JSON Schema、校验、审计、超时与降级策略。
9. 鉴权、越权防护、文件上传、隐私和审计方案。
10. 最小测试策略、迁移顺序和按阶段开发任务列表。
11. 尚需产品确认的问题，最多 5 个，并给出推荐默认值。

请特别检查这些失败场景：
- 用户重复点击提交。
- 自动保存与提交同时发生。
- 一批题只有部分 AI 判定成功。
- AI 输出非法 JSON 或与标准答案冲突。
- 管理员在用户答题期间修改或下架题目。
- 同一导入任务重复执行。
- 用户试图读取其他账号的练习或统计。
```

## 3. 使用顺序

1. 先让前端设计 AI 输出信息架构和核心页面，不急于生成完整代码。
2. 再让后端架构 AI 根据同一份 PRD 输出数据模型和 API 契约。
3. 对齐答题前 DTO、答题后 DTO、异步任务状态和答案来源枚举。
4. 契约确认后，再分别生成前端页面和后端模块。

如果两个方案冲突，以 PRD 中“答案可信度、批次延迟反馈、历史可复现、账号数据隔离”四条原则为准。
