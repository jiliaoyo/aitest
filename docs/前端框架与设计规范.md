# AI 刷题 App 前端框架与设计规范

> 版本：v0.1  
> 状态：首版开发基线  
> 技术栈：Vue 3 + TypeScript  
> 适用范围：学习端与管理端 Web  
> 上游文档：《AI刷题App-产品需求文档》《后端框架结构规范》

## 1. 目标

本规范统一首版前端的工程结构、页面范围、交互状态、API 边界和视觉规则。开发时优先保证：

1. 用户可以完成“创建练习 → 批次答题 → 整批提交 → 查看结果 → 专项重练”的闭环。
2. 提交前不显示或缓存标准答案、判分结果、解析及非原题翻译。
3. 官方/人工审核结果与 AI 判定清晰分层。
4. 自动保存、提交、AI 分析和导入任务都有可恢复的失败状态。
5. 管理员能对照原文审核题目、答案和分类后再发布。
6. 手机浏览器可以完成核心学习流程，但首版不追求原生 App 体验。

## 2. 设计原则

- **学习优先**：界面安静、阅读清晰，不让动画和 AI 文案抢占注意力。
- **延迟反馈**：整批提交前不显示任何答案线索。
- **可信来源**：界面展示的是后端返回的来源枚举，不根据文案自行推断。
- **状态明确**：加载、空数据、失败、无权限和异步处理中都必须有稳定页面状态。
- **路由即位置**：正式实现使用 URL 表达页面和筛选条件，不用单页内状态模拟全部页面。
- **少依赖**：浏览器和 Vue 已能完成的能力不再引入库。
- **服务端为事实源**：正确率、薄弱点和推荐数字由后端计算，前端只展示和格式化。

## 3. 技术选型

### 3.1 首版依赖

| 用途 | 选择 |
| --- | --- |
| 构建工具 | Vite |
| UI 框架 | Vue 3 Composition API + `<script setup>` |
| 类型 | TypeScript 严格模式 |
| 路由 | Vue Router |
| HTTP | 浏览器原生 `fetch` |
| 样式 | 原生 CSS + CSS Custom Properties |
| API 类型 | 根据后端 `openapi.yaml` 生成 TypeScript 类型 |
| 单元/组件测试 | Vitest + Vue Test Utils |

### 3.2 首版不引入

- Pinia：共享状态只有当前会话，先用一个轻量 session 模块。
- Axios：原生 `fetch` 已满足 Cookie、JSON、取消和错误处理。
- UI 组件库：会覆盖现有视觉语言，首版组件数量也不值得引入。
- Tailwind 或 CSS-in-JS：原生 CSS 足够，避免两套样式抽象。
- 图标库：首版使用少量内联 SVG。
- TanStack Query：页面数据流简单，等出现复杂缓存和失效问题再加。
- 图表库：正确率和趋势先用数字、表格和 CSS 进度条。
- 日期库：API 使用 RFC 3339，展示用 `Intl.DateTimeFormat`。
- WebSocket：AI 结果和导入进度先短轮询。

## 5. 依赖与数据方向

```text
router
  └── page
       ├── api/client
       ├── feature component
       └── shared component
```

- 页面负责首次加载、路由参数和页面级状态。
- 展示组件通过 props 获取数据，通过 emits 报告用户操作。
- composable 只承载真实复用或复杂状态，如自动保存；不把普通三行请求包装成 composable。
- 子组件不能直接修改 session，也不能自行跳转到无关功能页面。
- API DTO 与表单 model 分开，避免编辑中的临时状态污染服务端数据。
- 不在组件中保存可由后端重新计算的正确率和薄弱点。

### 6.4 路由规则

- 页面必须使用 Vue Router，不用 `localStorage` 保存当前页面名。
- 列表筛选、排序、分页游标尽量放入 query string，刷新后保持筛选。
- 进入受保护路由前先获取 `/api/v1/me`。
- 未登录访问受保护路由跳转 `/login?redirect=原路径`。
- 普通用户不渲染管理导航；访问 `/admin/*` 显示 403 页面。
- 用户访问不存在或不属于自己的资源时显示统一 404，不泄露资源是否存在。
- 登录后若有安全的站内 `redirect` 则返回原页面，否则进入 `/`。

## 7. 应用壳层与导航

### 7.1 学习端

- 桌面：顶部栏 + `220px` 左侧导航 + 主工作区。
- 学习导航：学习概览、创建练习、当前练习、练习历史、错题本、知识点。
- “当前练习”只有存在 `active` 批次时展示，并链接到具体批次。
- 账号菜单包含个人设置和退出。

### 7.2 管理端

- 管理端沿用同一视觉系统，但使用独立导航组。
- 管理导航：内容概览、题目、导入任务、知识点、来源、举报。
- 顶部明确显示“管理端”，避免管理员误以为正在学习端操作。
- 学习端与管理端可以相互切换，但管理入口只对管理员可见。

### 7.3 手机端

- `920px` 以下取消固定侧栏，改为顶部下方的横向滚动主导航。
- 管理端表单与审核页使用页面内二级导航，不把所有入口挤在一行。
- 当前路由使用 `aria-current="page"`，导航不能只靠颜色表示选中。

## 8. 状态管理

### 8.1 当前账号

`app/session.ts` 只保存：

- `/me` 请求状态。
- 当前用户 ID、显示名、角色和默认级别。
- `refreshSession()` 与 `clearSession()`。

它使用 Vue `shallowRef` 即可，不引入全局状态库。密码、Cookie 和重置令牌不能进入应用状态或 `localStorage`。

### 8.2 页面数据

- 页面进入时请求，离开页面后默认释放。
- 同一个页面内的重复请求可以复用当前响应，不做全站缓存系统。
- 请求中的页面显示骨架或明确的加载状态。
- 页面切换时用 `AbortController` 取消不再需要的读请求。
- 关键写操作成功后直接更新当前页面数据或重新请求，不设计通用缓存失效层。

### 8.3 URL 状态

以下状态进入 URL：

- 题目、历史、错题、知识点和举报的筛选与排序。
- 管理列表当前状态筛选。
- 登录后返回路径。

以下状态不进入 URL：

- 当前输入的密码。
- 未提交答案内容。
- 弹窗开关和 toast。
- 管理员尚未保存的表单正文。

### 8.4 本地存储

只允许两个用途：

1. 自动保存失败时，按 `practice-draft:{sessionId}` 临时保存未同步答案。
2. 按 `practice-submit-key:{sessionId}` 保存当前批次的提交幂等键，保证刷新后重试仍用同一个键。

服务端保存或提交成功后立即清理对应本地数据。不要把标准答案、结果 DTO、用户资料或管理内容长期写入本地存储。

## 9. API 客户端

### 9.1 `client.ts` 职责

- 基础路径统一为 `/api/v1`。
- 所有请求使用 `credentials: 'include'`。
- JSON 请求自动设置 `Content-Type`。
- 统一解析成功响应和后端错误结构。
- 为每个请求支持 `AbortSignal`。
- `401` 清理 session 并跳转登录。
- `403`、`404` 交由页面显示，不自动改写成通用错误。
- 网络失败返回稳定的前端错误类型，不依赖浏览器英文错误文案。

建议保持一个函数即可：

```ts
request<T>(path, { method, body, signal, headers }): Promise<T>
```

只有上传需要单独的 `upload()`，由浏览器设置 multipart boundary。

### 9.2 错误处理

```ts
type ApiError = {
  status: number
  code: string
  message: string
  requestId?: string
}
```

- 页面分支只判断稳定的 `code`，用户提示优先使用后端 `message`。
- 未知错误显示“操作失败，请重试”，并附可复制的 `requestId`。
- 表单字段错误映射到具体字段；全局 toast 不能替代表单错误。
- 不把后端堆栈、原始 AI 输出或内部错误展示给用户。

### 9.3 API 类型

- `docs/后端框架结构规范.md` 和后端 `api/openapi.yaml` 是契约来源。
- 生成的类型使用后端 `camelCase` 字段和 `snake_case` 枚举值。
- 页面禁止使用 `any` 绕过生成类型。
- 后端契约尚未生成时，只手写当前正在实现的最小 DTO，不复制整份数据库模型。

## 10. 数据可信度边界

### 10.1 答题前题目

答题页允许使用的字段：

```ts
type PracticeItemBeforeSubmit = {
  id: string
  position: number
  type: 'single_choice' | 'multiple_choice' | 'fill_blank' | 'short_answer'
  material: null | {
    id: string
    title?: string
    content: string
  }
  stem: string
  options: Array<{ id: string; label: string; text: string }> | null
  savedAnswer: { optionIds: string[] } | { text: string } | null
  markedForReview: boolean
  savedAt: string | null
}
```

答题前禁止出现：

- `correctAnswer`、`answerKey`、`answerAuthority`。
- `gradingStatus`、正确/错误状态。
- 官方解析或 AI 解析。
- 不是原题一部分的中文翻译。
- 会暗示答案的知识点、难度解释或推荐理由。

前端不能仅靠隐藏 DOM 防泄漏；这些字段必须根本不在响应中。

### 10.2 答题后结果

结果页按后端字段直接分层：

```ts
type GradingStatus =
  | 'correct'
  | 'incorrect'
  | 'unanswered'
  | 'pending'
  | 'failed'

type AnswerAuthority = 'official' | 'human_verified' | null
type GradingSource = 'deterministic' | 'ai' | null
type ExplanationSource = 'official' | 'human_verified' | 'ai' | null
```

- `confirmed` 只展示官方和人工审核答案形成的正式正确率。
- AI 区域分别展示 `completed`、`correct`、`pending`、`failed`，不能用含义不明的“1 / 2 AI 判定”。
- AI 尚未全部完成时，不显示完整 AI 正确率。
- 标准答案来源与解析来源分别展示；“已审核答案 + AI 解析”是合法组合。
- `unanswered` 有权威答案时计入正式题数并显示未作答；无权威答案时不进入正确率。

### 10.3 学习统计

- 前端使用后端返回的 `recentWrongCount` 和 `consecutiveWrongCount`，不混用名称。
- 推荐卡必须展示样本区间、题数、错误数和推荐原因。
- 样本不足时显示“数据不足，建议综合练习”，不伪造薄弱点。
- 所有百分比由后端返回小数，前端只做同一种舍入格式。

## 11. 核心流程

### 11.1 登录

1. 用户输入邮箱和密码。
2. 提交时按钮禁用并显示“登录中”。
3. 成功后刷新 session，跳转安全的站内 `redirect`。
4. 凭证错误显示在表单顶部，不清空邮箱。
5. 网络错误保留全部非密码字段，允许重试。

### 11.2 创建练习

1. 选择级别、科目和范围。
2. 范围可以是综合、知识点、错题或系统推荐。
3. 选择变化后请求 `/practice/availability`，显示真实可用题量。
4. 默认 20 题，可选 10、20、30；超过可用数量时禁用开始按钮。
5. 题量不足不自动放宽条件，用户确认较小题量后重新创建。
6. 创建成功跳转 `/practice/{sessionId}`。

选择控件优先使用原生 radio、checkbox 和 select。卡片式选择仍需保留原生 input，不用普通按钮模拟单选。

### 11.3 自动保存

状态固定为：

```text
idle → saving → saved
           └──► error → saving
```

实现规则：

- 用户修改答案后立即更新界面，约 500 毫秒后保存。
- 同一题只允许一个保存请求进行中；请求期间再次修改时标记 dirty，完成后立即保存最新值，避免旧请求覆盖新答案。
- `saved` 展示后端返回的 `savedAt`。
- 保存失败时将最新答案写入该批次本地草稿，并显示固定重试入口。
- 切题不阻止当前保存，返回该题时继续显示本地最新值。
- 重新打开批次时合并服务端答案和本地失败草稿；有冲突时本地未同步答案优先，并提示尚未同步。

### 11.4 整批提交

1. 停止新的 debounce timer，读取界面中的全部最终答案。
2. 统计未答题和待检查题，显示确认弹窗。
3. 用户确认后生成并保存一个 `crypto.randomUUID()` 幂等键。
4. 提交请求携带完整最终答案和 `Idempotency-Key`，不依赖自动保存是否已经完成。
5. 提交按钮禁用并显示“提交中”，防止重复点击。
6. 成功后清理本地草稿和幂等键，跳转结果页。
7. 网络失败保留同一个幂等键与答案，按钮允许重试。
8. 后端返回批次已提交时直接进入现有结果，不创建第二份成绩。

确认弹窗必须支持键盘焦点约束、Esc 取消和清晰的“继续答题 / 确认提交”操作。

### 11.5 结果与 AI 分析

- 第一次进入立即展示确定性成绩，不等待 AI。
- 批次为 `grading` 时每 3 秒重新请求结果。
- 页面不可见时暂停轮询，恢复可见后立即请求一次。
- `completed` 或 `analysis_failed` 后停止轮询。
- 页面卸载时清除 timer 和请求。
- 部分 AI 失败时保留已知成绩，并在具体题目显示“分析失败，稍后重试”。
- 结果页允许用户举报题干、答案、解析、分类或 AI 判定。

### 11.6 材料题

- 桌面答题布局为题目区 + 材料/进度区双栏。
- 共享材料切换小题时保持可见，阅读位置不重置。
- 右侧先显示材料，下面显示答题进度，不增加第三栏。
- 手机端材料默认展开；用户折叠后保持当前批次内的折叠状态。
- 文章、题干和选项必须来自答题前 DTO，不额外展示翻译。

### 11.7 问题反馈

- 入口放在结果页每题详情内。
- 用户选择问题类型并填写可选说明。
- 前端只发送 `practiceItemId`、问题类型和说明；题目版本、用户答案与判分上下文由后端补全。
- 提交成功后禁用重复提交，允许继续浏览结果。

### 11.8 导入与审核

```text
上传 → 提取中 → AI 整理中 → 待审核 → 发布
                  └──────────────► 失败/重试
```

- 上传页先显示支持格式和大小限制，再选择文件。
- 上传后进入任务详情，通过短轮询显示阶段和错误。
- 审核页左侧原文、右侧结构化表单；小屏改为“原文 / 结构化”页签。
- 审核字段至少包括：材料关系、题型、题干、选项、标准答案/可接受答案、答案来源、来源解析、级别、科目、知识点和异常项。
- 选择“官方答案”或“人工审核答案”时必须填写标准答案。
- AI 建议答案与来源答案分区显示，管理员明确确认后才能发布。
- 保存草稿、提交审核和发布是三个不同操作，不能用一个按钮自动串联。

## 12. 页面设计

### 12.1 学习端

| 页面 | 核心模块 | 必须覆盖的状态 |
| --- | --- | --- |
| 登录/注册 | 账号表单、错误、找回入口 | 提交中、字段错误、凭证错误、网络失败 |
| 仪表盘 | 今日建议、薄弱点、最近练习、继续答题 | 新用户空状态、数据不足、加载失败 |
| 创建练习 | 级别、科目、范围、题量、预览 | 可用量加载、题量不足、创建失败 |
| 批次答题 | 材料、题目、答案、题号、标记、保存、提交 | 保存中/成功/失败、未答确认、提交失败 |
| 结果 | 正式成绩、AI 状态、逐题解析、建议 | 判分中、部分失败、题目下架、批次不存在 |
| 历史 | 批次列表、筛选、继续/查看 | 空状态、分页失败 |
| 错题本 | 知识点筛选、错题、重练 | 无错题、题目下架 |
| 知识点列表 | 级别/科目筛选、个人统计、搜索 | 无统计、无正文、加载失败 |
| 知识点详情 | 讲解、误区、例句、个人数据、专项练习 | 未发布、样本不足、无相关题目 |
| 设置 | 默认级别、账号操作 | 保存中、保存成功、保存失败 |

### 12.2 管理端

| 页面 | 核心模块 | 必须覆盖的状态 |
| --- | --- | --- |
| 内容概览 | 草稿、待审核、已发布、异常、举报 | 空数据、加载失败 |
| 题目列表 | 搜索、分类、状态、来源筛选 | 空结果、分页、批量失败 |
| 题目编辑 | 材料、题型、选项、答案、解析、分类、版本 | 校验失败、并发修改、已下架 |
| 导入任务 | 上传、任务队列、阶段、错误 | 上传失败、提取失败、AI 失败 |
| 导入审核 | 原文对照、完整结构化字段、异常 | 未保存离开、发布校验失败 |
| 知识点管理 | 树、正文、例句、状态 | 名称冲突、父子层级错误 |
| 来源管理 | 来源、章节、授权说明 | 缺少授权说明、被题目引用 |
| 举报处理 | 类型、题目版本、上下文、处理结果 | 已处理、题目已改版、重算提示 |

## 13. 页面状态组件

`AppStatus.vue` 只覆盖四种通用页面状态：

| 状态 | 内容 | 操作 |
| --- | --- | --- |
| `loading` | 骨架或“加载中” | 无 |
| `empty` | 为什么为空 | 页面主操作 |
| `error` | 可理解错误 + request ID | 重试 |
| `forbidden` | 无权限说明 | 返回学习端 |

业务状态如 `grading`、`analysis_failed`、`saving` 放在所属页面，不扩展成通用状态框架。

规则：

- 首次页面加载使用骨架；局部按钮操作使用按钮 loading。
- 空状态不伪造示例统计，应给出下一步操作。
- toast 只用于短暂成功反馈，不承载保存失败、表单错误或提交结果。
- 删除、下架、发布、提交等不可轻易撤销操作需要确认。

## 14. 视觉系统

### 14.1 设计语言

以近白背景、清晰边界和钴蓝行动色构成安静精确的学习工作台。默认无阴影，通过边框、留白和字号建立层级。单个局部任务只保留一个主要实心按钮。

### 14.2 颜色令牌

```css
:root {
  --bg: oklch(99% 0.002 240);
  --surface: oklch(100% 0 0);
  --fg: oklch(18% 0.012 250);
  --muted: oklch(54% 0.012 250);
  --border: oklch(92% 0.005 250);
  --accent: oklch(58% 0.18 255);
  --success: oklch(52% 0.14 150);
  --warning: oklch(64% 0.14 75);
  --danger: oklch(56% 0.18 25);

  --accent-soft: color-mix(in oklch, var(--accent) 14%, transparent);
  --success-soft: color-mix(in oklch, var(--success) 12%, transparent);
  --warning-soft: color-mix(in oklch, var(--warning) 14%, transparent);
  --danger-soft: color-mix(in oklch, var(--danger) 12%, transparent);
  --fg-soft: color-mix(in oklch, var(--fg) 6%, transparent);
}
```

- `accent`：主要操作、当前导航、进度和 AI 来源。
- `success`：保存成功、确定性正确、已发布。
- `warning`：待分析、需确认、保存未同步。
- `danger`：错误、失败、破坏性操作。
- 状态不能只靠颜色，必须同时有文字或图标。
- 不使用紫色渐变、第二品牌色、大面积状态底色或装饰性色。

### 14.3 字体

```css
--font-display: -apple-system, BlinkMacSystemFont, 'SF Pro Display', system-ui, sans-serif;
--font-body: -apple-system, BlinkMacSystemFont, 'SF Pro Text', system-ui, sans-serif;
--font-japanese-serif: 'Hiragino Mincho ProN', 'Yu Mincho', 'Noto Serif JP', serif;
--font-mono: ui-monospace, 'SF Mono', Menlo, monospace;
```

- 页面标题使用 `--font-display`。
- 正文、表单和导航使用 `--font-body`。
- 阅读材料使用 `--font-japanese-serif`，`16–17px`，行高约 `1.9`。
- 数字、日期、题号和状态元数据使用 `--font-mono`。
- 正文默认 `15px / 1.55`，辅助说明 `12–13px`。
- `h1` 使用 `clamp(34px, 5vw, 60px)`；手机上避免标题占据整屏。

### 14.4 布局

- 桌面主容器最大宽度 `1240px`，水平内边距 `28px`。
- 顶部导航约 `68px`，可 sticky；半透明背景需要有不支持 `backdrop-filter` 的纯色回退。
- 主工作区桌面内边距：顶部 `34px`，左右 `clamp(22px, 4vw, 56px)`，底部 `64px`。
- 卡片圆角 `14px`，边框 `1px solid var(--border)`，默认内边距 `22px`。
- 网格间距 `18–22px`，按钮圆角 `9px`。
- 表格数字列右对齐；手机端表格可以横向滚动，但页面不能整体横向滚动。

### 14.5 断点

- `> 920px`：左侧导航，多栏布局，材料 sticky。
- `561–920px`：横向主导航，页面单栏，材料取消 sticky。
- `<= 560px`：卡片内边距 `18px`，指标单列，主要按钮可占满宽度。
- 触控目标至少 `44 × 44px`。
- 不根据设备类型分支业务逻辑，只用 CSS 调整布局。

## 15. 核心组件

### 15.1 必要共享组件

- `AppShell`：权限对应的导航和主工作区。
- `AppStatus`：加载、空、错误、无权限。
- `StatusBadge`：统一状态文案和语义颜色。
- `ConfirmDialog`：提交、发布、下架等确认。

### 15.2 练习组件

- `QuestionCard`：按题型渲染原生表单控件。
- `MaterialPanel`：共享材料和折叠状态。
- `QuestionNavigator`：题号、已答、未答、待检查和当前位置。
- `SaveStatus`：保存中、已保存、失败重试。
- `ResultItem`：用户答案、判分、答案来源和解析来源。

### 15.3 管理组件

- `QuestionEditor` 只有在新建题目和导入审核都实际复用时才抽出。
- 题型不同的答案编辑器可以按单选、多选、填空、简答拆分。
- 原文对照面板属于导入审核，不抽成全站通用 split-pane 框架。

## 16. 表单规范

- 使用原生 `input`、`select`、`textarea`、`radio`、`checkbox` 和 `button`。
- 每个字段有可点击的 `label`，错误使用 `aria-describedby` 关联。
- 提交后聚焦第一个错误字段，并在表单顶部显示错误摘要。
- 选项 ID 由前端稳定保存，管理员调整顺序时不能用展示字母作为数据库身份。
- 未保存的管理表单离开路由前提示，但不要拦截未修改表单。
- 发布按钮只有表单保存且通过前端基础校验后启用；后端仍执行最终校验。
- 文件选择使用原生 `<input type="file">`，前端限制仅作提示，服务端负责安全校验。

## 17. 无障碍

- 所有功能可用键盘完成。
- 焦点状态使用至少 `3px` 可见外描边，不移除浏览器焦点而不提供替代。
- 当前导航使用 `aria-current="page"`。
- 卡片式单选保留真实 radio 和 `fieldset/legend`。
- 答案保存状态使用 `role="status"`；持续更新不能频繁打断屏幕阅读器。
- 错误摘要使用 `role="alert"`，普通 toast 使用礼貌播报。
- 弹窗打开后焦点进入弹窗，关闭后回到触发按钮。
- 状态、正确错误和掌握程度不能只靠颜色。
- 日文正文标记正确语言；页面中文使用 `lang="zh-CN"`，局部日文使用 `lang="ja"`。
- 动画遵守 `prefers-reduced-motion`，首版不做非必要动画。

## 18. 性能与体验

- 路由页面使用动态导入，学习端和管理端分别按需加载。
- 首屏不预加载管理端页面。
- 不对每次输入字符请求 availability；筛选变化短暂 debounce。
- 长列表使用后端分页，不在首版引入虚拟列表。
- 图片和文件预览按需加载，题目文本不做客户端 Markdown 动态执行。
- AI 分析与导入进度使用一个可清理的短轮询，不创建全局轮询管理器。
- 使用浏览器 `Intl` 格式化日期和百分比，保持同一页面精度一致。

## 19. 前端安全

- 认证只依赖 HttpOnly Cookie，前端不保存 session token。
- 所有文本默认使用 Vue 插值渲染，不使用 `v-html` 渲染题目、解析或 AI 内容。
- 若知识点正文以后支持 Markdown，使用固定白名单渲染器并清理 HTML；P0 可先显示纯文本。
- 站内 redirect 必须以 `/` 开头且不能以 `//` 开头，防止开放重定向。
- 上传预览不执行文件内容，不把本地绝对路径发送给服务端。
- 管理导航隐藏不是鉴权；所有管理 API 仍由后端校验角色。
- 生产环境不在控制台打印用户答案、AI 输入、邮箱和 API 完整响应。

## 20. 测试规范

### 20.1 最小自动化测试

1. 答题前 DTO 类型和页面不读取答案、解析或判分字段。
2. 同一题连续快速修改时，自动保存最终值不会被旧请求覆盖。
3. 保存失败后本地草稿可恢复，成功后会清理。
4. 重复点击提交只发一个请求；网络重试复用同一幂等键。
5. 结果页将正式正确率、AI 完成、AI 待处理和 AI 失败分开显示。
6. 普通用户看不到管理导航，访问管理路由进入 403。
7. 材料题切换小题后材料内容和阅读位置保持。
8. 导入审核未填写标准答案时不能选择权威答案并发布。

### 20.2 测试方式

- 纯格式化和状态函数使用 Vitest。
- 自动保存、提交、结果分层使用 Vue Test Utils 组件测试。
- HTTP 使用最小 fetch stub，不引入大型 mock 框架。
- 首版完成后人工走查一次桌面、`768px` 和 `390px` 三种宽度的完整批次流程。
- 无障碍人工走查至少覆盖键盘答题、提交弹窗和管理员表单错误。

## 21. 编码规范

- TypeScript 开启 `strict`、`noUncheckedIndexedAccess`。
- 使用 `<script setup lang="ts">`，不混用 Options API。
- props、emits 和 API 响应必须有明确类型。
- 模板不写复杂表达式；超过一次条件组合就放入具名 computed。
- 不使用 `any`、非必要类型断言和深层全局 CSS。
- CSS class 使用 kebab-case；状态优先用 `data-state`，不动态拼接大量 class。
- 用户可见文案集中在页面或组件，不为首版提前搭建国际化系统。
- 日文题目内容来自 API，不写死进业务组件。
- 一个功能分支、轮询或并发保存逻辑至少留下一个最小测试。

## 22. 开发顺序

### 阶段 1：应用骨架与刷题闭环

1. 初始化 Vite、Vue、TypeScript、Router 和基础 CSS。
2. 完成 API client、session、登录和权限路由。
3. 完成题目类型、创建练习和答题前 DTO。
4. 完成材料题、自动保存、提交确认和幂等提交。
5. 完成结果分层、历史和基础错误状态。

### 阶段 2：学习档案

1. 仪表盘和继续练习。
2. 错题本、知识点列表和详情。
3. 薄弱点推荐与专项练习跳转。

### 阶段 3：管理端与 AI 状态

1. 管理壳层、题目列表和完整编辑表单。
2. 导入上传、任务进度和原文对照审核。
3. AI 判定轮询、部分失败和举报处理。
4. 知识点与来源管理。

不要为阶段 3 提前构建通用后台低代码表格或表单生成器。

## 23. 首版完成定义

1. 登录用户能从任意核心页面刷新并恢复正确位置和服务端数据。
2. 用户能创建并完成一批练习，自动保存失败和提交失败均可恢复。
3. 提交前网络响应和前端状态中不存在答案、解析和非原题翻译。
4. 正式正确率与 AI 估算不混合，所有 AI 内容有来源标签。
5. 阅读材料在桌面和手机上都能持续查看。
6. 普通用户不能看到或进入管理端。
7. 管理员能填写并审核真正的标准答案，而不只是选择答案来源。
8. 所有页面具有加载、空、失败和权限状态中的适用部分。
9. 桌面和 `390px` 手机宽度均可完成完整练习流程。
10. 自动保存、幂等提交、结果分层和权限路由的最小测试通过。

## 24. 明确跳过

- 原生移动端、PWA 离线题库和推送通知。
- 聊天式 AI、社区、排行榜、会员和支付。
- UI 框架、图表库、全局数据缓存和 WebSocket。
- 复杂动画、皮肤系统、国际化框架和低代码后台。
- 在真实性能或维护问题出现前建立通用组件平台。

这些能力等首版数据和实际使用证明需要时再增加。
